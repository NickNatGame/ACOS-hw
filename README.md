# Обедающие философы: TCP-философы

Новые программы написаны на C11: `philosophers_tcp_server` управляет вилками и
FIFO, `philosophers_tcp_client` выполняет поведение одного философа, а
`philosophers_tcp_observer` показывает общую картину. Клиенты
запускаются независимо, общей памяти, очередей сообщений и проверки удалённых
PID здесь нет. Сервер обслуживает неблокирующие сокеты через `poll()` в одном
процессе. Размышление и еда проходят в процессах клиентов, поэтому несоседние философы
могут есть одновременно. Обе вилки выдаются первому в FIFO сразу, без удержания
одной вилки во время ожидания второй.

Сборка быстрого примера:

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build -j 4
```

В первом терминале (два философа, по три цикла):

```bash
./bin/philosophers_tcp_server 127.0.0.1 5050 2 3 100 200 100 200 3000 0 42 fifo 10000
```

После `ГОТОВО` во втором и третьем терминалах соответственно:

```bash
./bin/philosophers_tcp_client 127.0.0.1 5050 1
./bin/philosophers_tcp_client 127.0.0.1 5050 2
```

Наблюдателя можно подключить до философов или во время моделирования:

```bash
./bin/philosophers_tcp_observer 127.0.0.1 5050
```

Справка: `--help` у каждой программы.

После IP и порта сервер принимает параметры:

| Параметр | Назначение | По умолчанию |
|---|---|---:|
| `N` | Число философов и вилок, 2..256 | 5 |
| `cycles` | Число приёмов пищи каждого философа, от 1 | 3 |
| `think_min`, `think_max` | Диапазон размышления, ms, от 0 | 500, 1500 |
| `eat_min`, `eat_max` | Диапазон еды, ms, от 1 | 400, 1000 |
| `max_wait` | Максимальное ожидание вилок, ms, от 1 | 5000 |
| `display_delay` | Зарезервирован, снимки получает наблюдатель | 120 |
| `seed` | Начальное значение генератора | 42 |
| `strategy` | Только `fifo` | fifo |
| `time_limit` | Лимит моделирования, ms, 0 - без лимита | 60000 |

Числа задаются только цифрами, без знаков и пробелов, до `INT_MAX` включительно.
Сервер выводит
подключения, полученные запросы, выдачу/освобождение вилок и причину остановки.
Клиент выводит только собственные размышления, голод, запросы и получение обеих
вилок, ожидание, еду и завершение. Наблюдатель после каждого изменения печатает
все состояния философов и владельцев вилок.

### Протокол TCP

Каждый кадр = ровно 24 байта: шесть беззнаковых 32-битных чисел в сетевом
порядке байтов: `version, type, id, value, count, cycles`. `version=1`,
`id=1..N` для философа, `id=0` для регистрации наблюдателя и его CONFIG/STOP.
В CONFIG философа `value` - уже завершённые циклы, `count=N`, `cycles` - цель.
В SNAPSHOT `id` - философ, `value` - состояние (0..6), `count` и `cycles` -
владельцы левой и правой вилок (0 если свободна). 
Полный снимок - N кадров по порядку ID.
Не передаются сырые C-структуры и указатели. Частичные чтения сохраняются до
полного кадра, несколько кадров в потоке разбираются отдельно. Отправка учитывает
частичную запись и ограничена 100 ms на кадр.

| Тип | Направление | Значение `value` |
|---|---|---|
| `JOIN=1` | Клиент -> сервер | 0, запрос места `id` |
| `CONFIG=2` | Сервер -> клиент | 0, `count=N`, `cycles` - число циклов |
| `START=3` | Сервер -> клиент | Длительность первого размышления, ms |
| `HUNGRY=4` | Клиент -> сервер | 0, запрос двух вилок |
| `EAT=5` | Сервер -> клиент | Длительность еды, ms; обе вилки уже выделены |
| `FINISH=6` | Клиент -> сервер | 0, еда закончена, можно освободить вилки |
| `CONTINUE=7` | Сервер -> клиент | Длительность следующего размышления, ms |
| `STOP=8` | Сервер -> клиент | Код завершения |
| `OBSERVER_JOIN=9` | Наблюдатель -> сервер | Регистрация, ID=0 |
| `SNAPSHOT=10` | Сервер -> наблюдатель | Состояние философа и соседних вилок |

На подключение всех N философов отводится 60 секунд с запуска сервера. Модельное
время начинается после регистрации всех участников. Повторный ID отклоняется,
сообщения зарегистрированного клиента привязаны к его соединению. Сервер проверяет
версию, поля, порядок действий и запрещает завершать размышление/еду раньше срока.
Он назначает длительности своим генератором с `seed`, порядок событий зависит от
сети и планировщика. Ожидание у сервера считается от получения `HUNGRY` до выдачи
`EAT`, у клиента - до получения разрешения, поэтому включает сетевую задержку.

После последнего `FINISH` философ ждёт общей остановки. Успех - если все N участников
выполнили свои циклы. Коды: 0 - успех, 1 - ошибка/обрыв/неполное подключение,
2 - лимит времени или ожидания, 130/143 - SIGINT/SIGTERM серверу. Сервер отправляет
`STOP` подключённым философам и закрывает сокеты, клиент обнаруживает также EOF.
При Ctrl+C клиенту он закрывает соединение и возвращает код своего сигнала,
сервер освобождает обе вилки и убирает его заявку из FIFO. Прерванная еда не
засчитывается. Остальные философы продолжают работу. Повторный запуск клиента
с тем же ID продолжает оставшиеся циклы: сервер хранит их число в своей памяти.
Завершивший свои циклы клиент после возвращения ждёт общей остановки.
Отсутствующий философ не считается завершившим модель, общий лимит продолжает идти.

Одновременно допускаются до 32 наблюдателей. Они могут отключаться и подключаться
снова, каждый новый сразу получает полный текущий снимок. Ошибка отправки
наблюдателю отключает только этого наблюдателя. Незарегистрированное соединение
имеет 2 секунды на отправку JOIN. Сервер последовательно регистрирует новые
соединения, продолжая обслуживать действующих участников через poll.

При SIGINT/SIGTERM сервера он освобождает вилки, рассылает итоговый снимок и STOP
всем доступным наблюдателям и философам и закрывает сокеты. Клиенты завершаются
с кодом сервера.

TCP-тесты написаны на C. CMake собирает
`philosophers_tcp_tests` и добавляет его в CTest:

```bash
ctest --test-dir build --output-on-failure
./bin/philosophers_tcp_tests ./bin/philosophers_tcp_server ./bin/philosophers_tcp_client ./bin/philosophers_tcp_observer
```

Проверяются реальные 2 и 5 клиентов, число циклов, FIFO и владение вилками по
выводу сервера, параллельная выдача несоседям, частичные и объединённые кадры
в обоих направлениях, ранний `FINISH`, неверные ID/версия, повторный ID,
лимиты, SIGTERM серверу и всем клиентам, возвращение погибшего философа,
отключение во время еды с сохранением завершённых циклов, несколько наблюдателей,
их переподключение, гибель сервера и отсутствие участников.

Вывод каждого тестового процесса сохраняется в `tests/logs/run-XXXXXX/`.
Каждый запуск создаёт отдельную папку и печатает её путь, старые логи сохраняются.
Путь задан при сборке, поэтому это работает и при запуске через CTest из `build`.
