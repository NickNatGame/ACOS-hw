# Отчёт по заданию 2: вариант 5, «Обедающие философы»

Исполнитель: **Пичурин Никита**.

Группа: **БПИ253**.

Вариант: **5**

## Условие задачи

Несколько философов сидят за круглым столом. Каждый чередует размышление и еду.
Между соседями лежит вилка; для еды нужны обе соседние вилки. После еды они
освобождаются. Алгоритм одинаков для всех философов. Требуется исключить
взаимную блокировку и контролировать неограниченное ожидание.

Входные данные: количество философов и вилок, число циклов, диапазоны длительности
размышления и еды, стратегия получения вилок, максимальное ожидание и общий лимит.
Программа должна показывать действия философов, выдачу и освобождение вилок,
завершаться после всех циклов, по лимиту либо по сигналу пользователя.
Второе задание реализовано с использованием C11, POSIX и библиотеки pthread.

## Сценарий и отображение сущностей в потоки

За основу приянто первое задание, оттуда взял состояния философов, массив владельцев вилок,
кольцевую очередь и журнал. Последовательный переход
виртуального времени заменён асинхронным выполнением с реальными задержками.

В процессе работают N + 1 потоков:

| Сущность | Представление и поведение |
|---|---|
| Философ | Отдельный pthread, одна и та же функция `philosopher_main` для всех |
| Вилка | Элемент `fork_owner`: индекс владельца или −1, самостоятельного поведения нет |
| Арбитр | Общая функция `give_forks`, вызываемая рабочими потоками под мьютексом |
| Наблюдатель | Главный поток: снимки состояний, проверка остановки, ожидание потоков и итоги |

Философы проходят состояния «ожидает старта» -> THINKING -> HUNGRY -> EATING.
После еды начинается новое размышление, после последнего цикла -> DONE.
При досрочном завершении незавершённые участники получают STOPPED.

Для философа `i` нужны вилки `i` и `(i + 1) % N`. Число вилок равно числу философов.
Вилки и арбитр не выделяются в отдельные потоки, т.к. вилки являются ресурсами,
а решение арбитра выполняется внутри короткого действия.

Цикл работы философа:

1. Под мьютексом выбрать длительность и сообщить о начале размышления
2. Отпустить мьютекс на время реального ожидания
3. Под мьютексом перейти в голодное состояние, встать в FIFO и запросить вилки
4. Арбитр проверяет лимиты и выдаёт обе свободные вилки первому в очереди
   Для каждой выданной пары выполняется `sem_post` семафора получателя
5. Философ ждёт уведомления в `sem_wait` без удержания мьютекса, затем ест
   с задержкой также вне критической секции
6. Под мьютексом освободить обе вилки, засчитать завершённый цикл и передать
   возможность есть следующим заявкам. Повторить цикл либо завершить поток

## Мьютекс, семафоры и корректность

В `Simulation` находится один `pthread_mutex_t`. Он защищает состояния,
владельцев вилок, очередь, время, статистику, причину остановки и весь вывод.
Поэтому связанные сообщения одного действия не перемешиваются с другим действием,
а экран и лог получают одинаковую последовательность событий.
Мьютекс не удерживается при размышлении, еде, `sem_wait`, `sem_timedwait`
или `pthread_join`. Несоседние философы действительно могут есть одновременно.

Каждый философ имеет собственный безымянный семафор `wake`, начальное
значение которого равно 0. Он используется для старта, выдачи вилок и пробуждения
при остановке. Для задержек применяется `sem_timedwait` короткими интервалами
до 10 ms. Общий остановочный флаг проверяется после пробуждения

| Инвариант | Обоснование |
|---|---|
| У вилки не более одного владельца | Проверка и назначение обеих вилок выполняются под одним мьютексом |
| Еда разрешена только с двумя соседними вилками | EATING устанавливается только после назначения пары |
| Голодный не удерживает одну вилку | Пока пара недоступна, владение вообще не меняется |
| Взаимная блокировка исключена | Нет удержания одной вилки в ожидании другой, т.к. спящие не держат мьютекс |
| Новые заявки не вытесняют старые | Выдача идёт строго с головы очереди, обход запрещён |
| Ресурсы освобождаются до уничтожения | При остановке все потоки пробуждаются, затем выполняется join и очистка |

При конечной еде и предоставлении потокам времени очередь
исключает бесконечное вытеснение: перед заявкой не более N − 1 других заявок,
а новые встают сзади. Слишком долгое ожидание останавливается по `max_wait`. 
Очередь иногда оставляет свободные вилки
без дела, пока первая заявка ждёт свою пару.

## Пользовательский интерфейс

```text
./bin/philosophers [N] [cycles] [think_min] [think_max] [eat_min] [eat_max]
                   [max_wait] [display_delay] [seed] [strategy] [time_limit]
```

Аргументы позиционные; пропущенные справа получают значения по умолчанию:
`5 3 500 1500 400 1000 5000 120 42 fifo 60000`. Допустимые диапазоны приведены
в README. `-h` и `--help` показывают справку без создания лога.

Сообщение содержит прошедшее время, номер философа и событие: размышление,
голод, запрос/получение каждой вилки, начало/окончание еды, освобождение и завершение.
Снимки состояний показывают каждого философа, текущее ожидание и владельца
каждой вилки. Параметр `display_delay` задаёт период снимков, а 0 оставляет
только события и итоговый снимок. Он не отключает реальные задержки модели.

Общий генератор `rand()` инициализируется вызовом `srand(seed)` до создания потоков.
Все обращения к генератору выполняются под общим мьютексом. Планировщик определяет,
какому философу достанется очередное число, поэтому совпадение seed не означает
полного совпадения журналов. События измеряются монотонными часами,
проверки остановки выполняют рабочие потоки и главный поток с паузой 5 ms.

## Запуск и завершение

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build
./bin/philosophers
./bin/philosophers 5 3 10 30 20 40 1000 50 42 fifo 5000
```

| Исходные данные или событие | Результат | Код |
|---|---|---:|
| Все философы выполнили cycles | Потоки завершены, вилки свободны, статистика сохранена | 0 |
| Некорректные аргументы | Диагностика до открытия лога и запуска потоков | 1 |
| Ошибка памяти, pthread, семафора или вывода | Остановка с диагностикой, созданные потоки присоединяются | 1 |
| Ожидание больше max_wait | Новая еда не разрешается, ожидающие и едящие останавливаются | 2 |
| Достигнут time_limit, работа ещё осталась | Общая остановка с причиной | 2 |
| time_limit = 0 | Остаются cycles, max_wait и возможность прерывания | — |
| SIGINT / Ctrl+C | Штатная очистка и статистика | 130 |
| SIGTERM | Штатная очистка и статистика | 143 |

Ровно `max_wait` допустимо; превышение проверяется до выдачи вилок.
Главный поток замечает остановку с периодом около 5 ms, но точность до
миллисекунды и немедленное планирование потока не гарантируются.
`pthread_cancel` не применяется. Прерванная еда не засчитывается как цикл.

При невозможности создать все N потоков уже созданные потоки получают
уведомление об остановке и присоединяются. Семафоры и мьютекс уничтожаются,
динамические массивы освобождаются. Ошибка stdout не обрывает процесс через
SIGPIP, программа пытается сохранить итоги в лог. Ошибки записи/закрытия
также дают ненулевой код.

## Тестовые наборы и результаты

```bash
ctest --test-dir build --output-on-failure
./bin/philosophers_tests ./bin/philosophers
./tests/run_examples.sh
   или 
bash tests/run_examples.sh
```

CTest запускает 23 тестовые функции на C. Каждый запуск получает отдельный временный каталог.
Тесты по журналу независимо восстанавливают владельцев вилок и очередь,
проверяют длительности не короче заданных, отсутствие одновременной еды
соседей, совместную еду несоседей, статистику и освобождение всех вилок.
Проверяются параметры, большие длительности с коротким лимитом, 137 философов,
SIGINT/SIGTERM во время еды/ожидания и SIGINT во время долгого размышления,
ошибки открытия/записи лога и закрытый stdout. В сигнальных сценариях число
потоков дополнительно сверяется с N + 1 через.

Дополнительно проверен частичный отказ `pthread_create`, запуск 50 философов
при ограничении виртуальной памяти 64 MiB остановился на создании восьмого
потока, присоединил уже созданные потоки и завершился с кодом 1 без зависания.
Это отдельная ручная проверка, не дополнительная функция C-тестов.

Файл `tests/scenarios.txt` задаёт входные данные и ожидаемые коды завершения.
Скрипт `tests/run_examples.sh` запускает их, проверяет коды и обновляет журналы
в `tests`. Пример фактических результатов приведён ниже, конкретные времена
и номера первых получателей вилок зависят от планировщика.

| Набор | Аргументы | Итог |
|---|---|---|
| normal | `2 1 3 3 7 7 1000 0 42 fifo 1000` | 2 завершённых приёма пищи, код 0 |
| wait_timeout | `2 1 0 0 500 500 50 0 42 fifo 2000` | Превышение ожидания, еда прервана, код 2 |
| time_limit | `2 1 0 0 500 500 1000 0 42 fifo 50` | Общий лимит, еда прервана, код 2 |
| parallel | `5 2 0 10 30 30 1000 0 42 fifo 2000` | 10 завершённых приёмов пищи, несоседи едят одновременно, код 0 |

Полные результаты находятся в `tests/normal.log`, `tests/wait_timeout.log`,
`tests/time_limit.log`, `tests/parallel.log`. Во всех случаях после остановки
вилки свободны, число завершённых циклов и ожидания отражены для каждого участника.
