# Обедающие философы 3: POSIX-семафоры и разделяемая память

Процессная версия второго ДЗ на C11 для Linux/POSIX. Родитель создаёт N дочерних
процессов через `fork`, каждый ребёнок выполняет алгоритм одного философа.
Вилки, FIFO-очередь, состояния и статистика находятся в POSIX shared memory.
Общий семафор защищает модель и вывод; персональные семафоры уведомляют философов
о старте, выдаче вилок и остановке. Размышление и еда выполняются с реальными
задержками без удержания общего семафора. Доступны две отдельные программы:

| Программа | Создание и освобождение семафоров |
|---|---|
| `philosophers_unnamed` - версия на 4–5 | `sem_init(pshared=1)` в общей памяти, `sem_destroy` |
| `philosophers_named` - добавление на 6 | `sem_open`, `sem_unlink`, `sem_close` |
| `philosophers_coordinator` + `philosophers_participant` - добавление на 7–8 | Независимый запуск, именованные семафоры и POSIX shared memory |
| `philosophers_mq_coordinator` + `philosophers_mq_participant` - добавление выше 8 | Независимый запуск, POSIX-очереди сообщений и именованные семафоры |

Обе используют один алгоритм FIFO, парсер, журнал и контроль детей. При сборке
подключается соответствующий файл `src/fork_shared/semaphores_unnamed.c` или
`src/fork_shared/semaphores_named.c`. Команда `philosophers` сохранена как копия неименованной
версии для совместимости с прежними командами запуска.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build
./bin/philosophers_unnamed

./bin/philosophers_named --help
ctest --test-dir build --output-on-failure
./tests/run_examples.sh
./tests/run_examples.sh named
```

Нужны CMake 3.16+, компилятор C и Make или Ninja. POSIX-семафоры подключаются через
`Threads::Threads`, shared memory - через `rt`. Сторонних библиотек нет.
Команды выполняются из корня проекта.<br>
Сборка находится в `build`, программа -
в `bin/philosophers_unnamed` и `bin/philosophers_named`, тесты - в `bin/philosophers_tests`.
Чтобы отключить сборку тестов, задайте `-DBUILD_TESTING=OFF` при настройке CMake.

## Параметры

```text
./bin/philosophers [N] [cycles] [think_min] [think_max] [eat_min] [eat_max]
                   [max_wait] [display_delay] [seed] [strategy] [time_limit]
```

Те же аргументы принимают `philosophers_unnamed` и `philosophers_named`.
Аргументы задаются по порядку. Последние можно не указывать — тогда используются значения по умолчанию.
Числовой аргумент должен содержать только цифры `0`–`9`: знаки `+`/`-`, пробелы,
дроби и посторонние символы запрещены. Ведущие нули допустимы: `002` означает 2.
`-h` и `--help` работают только как единственный аргумент.

| Аргумент | Что задаёт | По дефолту |
|---|---|---:|
| N | Количество философов и вилок, от 2 до 256 | 5 |
| cycles | Сколько раз должен поесть каждый философ, минимум 1 | 3 |
| think_min, think_max | Диапазон времени размышления в миллисекундах | 500, 1500 |
| eat_min, eat_max | Диапазон времени еды в миллисекундах | 400, 1000 |
| max_wait | Максимальное ожидание вилок в миллисекундах | 5000 |
| display_delay | Реальная пауза между моментами событий, 0 — без пауз | 120 |
| seed | Начальное значение генератора случайных чисел | 42 |
| strategy | Способ выдачи вилок, поддерживается только fifo | fifo |
| time_limit | Общий лимит модельного времени, без лимита - 0 | 60000 |

Все числа — от 0 до INT_MAX, с дополнительными ограничениями из таблицы.
Верхняя граница диапазона должна быть не меньше нижней. Размеры массивов и
верхние оценки времени/статистики проверяются на переполнение. Проверка
переполнения консервативна: учитывает все циклы даже при коротком общем лимите.
Предел 256 не позволяет ошибочным аргументом запросить создание тысяч участников.
Даже в этом диапазоне запуск зависит от памяти и доступного числа процессов ОС.
При ошибке `fork` уже созданные дети пробуждаются и собираются через `waitpid`.
Параметры проверяются до открытия лога, создания общей памяти и запуска процессов.
При ошибке программа выводит диагностику в stderr и возвращает код 1.

Например, `./bin/philosophers 257`, `./bin/philosophers ' 5'` и
`./bin/philosophers 5 1abc` завершаются с ошибкой без создания `philosophers.log`.
Если журнал уже существовал, ошибка параметров не изменит его.

Проверки ввода входят в `ctest --test-dir build --output-on-failure`:
29 некорректных строк проверяются в каждой из 10 числовых позиций. Отдельно
проверяются ограничения параметров, стратегия, лишние аргументы, значения на
границах диапазонов и все варианты пропуска последних аргументов.

Быстрый пример с реальными короткими задержками:

```bash
./bin/philosophers 5 3 10 30 20 40 1000 50 42 fifo 5000
./bin/philosophers_named 5 3 10 30 20 40 1000 50 42 fifo 5000
```

В отличие от первого задания, длительности больше не являются виртуальными:
`display_delay=0` не ускоряет размышление и еду. Время измеряется через
`CLOCK_MONOTONIC` после создания процессов.
У каждого процесса своя копия `rand()`: родитель вызывает `srand(seed)`, философ
с индексом i — `srand(seed + i)`. Планировщик влияет на порядок действий и выдачу
вилок, поэтому seed не фиксирует весь журнал.

## Взаимодействие и завершение

Философ `i` использует вилки `i` и `(i + 1) % N`. Голодный философ добавляется
в FIFO. Арбитр под общим семафором выдаёт первому в очереди сразу обе свободные вилки
и вызывает `sem_post` его персонального семафора. Если хотя бы одна вилка занята,
остальные заявки не обходят первую. Несоседние философы могут есть одновременно.
Философ, ожидающий вилок, спит в `sem_timedwait` и не удерживает общий семафор.

Все события выводятся сразу: размышление, голод, запрос каждой вилки, получение,
еда и освобождение. `display_delay` задаёт только период дополнительных снимков
состояний и владельцев вилок. Родитель проверяет остановку с паузой 5 ms,
работающие философы также проверяют лимиты между действиями и во время задержек.
Ровно `max_wait` допустимо, превышение приводит к остановке до выдачи вилок.
Если достигнут `time_limit` и осталась незавершённая работа, программа останавливается.

Ctrl+C и SIGTERM устанавливают флаг в том процессе, который получил сигнал.
При остановке программа будит все персональные семафоры, выполняет `waitpid`,
освобождает вилки и сохраняет статистику. Сигнал можно отправить родителю или
всей группе процессов; Ctrl+C в терминале действует на всю foreground-группу.
Прерванная еда не засчитывается как завершённый цикл. Ожидание, после которого
еда не началась, учитывается отдельно. `time_limit=0` сохраняет число циклов,
контроль `max_wait` и возможность прерывания сигналом.

| Код | Причина |
|---:|---|
| 0 | Все циклы выполнены или показана справка |
| 1 | Ошибка параметров, shared memory, fork/семафоров, дочернего процесса или ввода-вывода |
| 2 | Превышено ожидание либо достигнут общий лимит |
| 130 | SIGINT, обычно Ctrl+C |
| 143 | SIGTERM |

## Общая память и аварийное завершение

Родитель создаёт объект `/philosophers-PID` через `shm_open` с `O_EXCL` и правами
0600. Сразу выполняется `shm_unlink`: имя удаляется, а объект существует, пока
открыт его дескриптор или сохраняется отображение. Место резервируется через
`posix_fallocate`, затем создаётся `mmap` с `MAP_SHARED`. После отображения
дескриптор закрывается. Резервирование позволяет обработать нехватку места
в `/dev/shm` до записи в отображённую память.

Все данные помещаются в один блок с массивами на `MAX_PHILOSOPHERS`; используются
первые N элементов. В общей структуре нет указателей на локальную память.
Поля `sem_t` в этом блоке используются только неименованной версией. Рабочие
указатели на семафоры находятся в локальных переменных процесса и наследуются
при `fork`,  в общей структуре указателей нет.

Именованная версия создаёт семафоры `/philosophers-PID-mutex` и
`/philosophers-PID-wake-i` через `sem_open(O_CREAT | O_EXCL, 0600, value)`.
Сразу после открытия выполняется `sem_unlink`, дети наследуют открытые семафоры
через `fork`, поэтому повторно открывать их по имени не требуется.
Имена удалены заранее, а сами объекты существуют до закрытия последней ссылки. Существующий
семафор с совпавшим именем не открывается и не удаляется, запуск завершается
с ошибкой.

Только родитель освобождает созданные семафоры после сбора всех детей:
`sem_destroy` в неименованной версии и `sem_close` в именованной. Затем выполняется
`munmap`. При частичной инициализации освобождаются только успешно созданные
семафоры.

Родитель проверяет детей через `waitpid(WNOHANG | WUNTRACED)`. Неожиданный выход
с ошибкой, гибель от сигнала или остановка ребёнка вызывают аварийное завершение
всего запуска с кодом 1. Ожидания общего семафора ограничены интервалами 10 ms:
родитель продолжает проверять детей, даже если погибший участник удерживал его.

При аварии родитель отправляет оставшимся детям SIGTERM, не ожидая общий семафор.
Если дети не завершились примерно за секунду, используется SIGKILL, затем
обязательный `waitpid`. Только после этого родитель приводит вилки в свободное
состояние и печатает итоги. При гибели посередине изменения модели статистика
может быть неполной; это аварийный исход, а не успешно выполненный цикл.
Ошибки stdout и лога дают код 1; закрытый pipe не завершает программу через SIGPIPE.

## Проверки

CTest запускает четыре набора: 31 функцию для неименованной версии, 32 для именованной,
сценарии независимых процессов с shared memory (`philosophers_session_tests`)
и с очередями сообщений (`philosophers_mq_tests`).
Кроме ввода и анализа FIFO/вилок по журналу,
проверяются реальные дочерние процессы, параллельная еда несоседей, сигналы
родителю и всей группе, SIGKILL/SIGSTOP отдельному ребёнку и повторные запуски.
После запусков проверяется отсутствие объявленных PID, имени общей памяти и
именованных семафоров с PID проверяемого запуска.

`tests/faults.c` подключается только к `philosophers_faults` и `philosophers_named_faults`
через подмены линкера `--wrap`. Автоматически воспроизводятся 12 сценариев:
отказы `shm_open`, резервирования памяти, `mmap`, общего и персонального семафоров,
частичный отказ `fork`, ошибка часов, ожидания и выдачи семафора, гибель и остановка
ребёнка с занятым общим семафором, SIGINT во время создания детей. Именованная
версия дополнительно проверяется при ошибках `sem_open`, `sem_unlink` и `sem_close`.
Обычные программы не содержат этих подмен и не читают тестовую переменную окружения.

Полный запуск вручную:

```bash
./bin/philosophers_tests ./bin/philosophers ./bin/philosophers_faults
./bin/philosophers_tests ./bin/philosophers_named ./bin/philosophers_named_faults named
```

Если передать только путь к обычной программе, выполняются 30 функций без подмен системных вызовов.
Скрипт `tests/run_examples.sh named` сохраняет отдельные примеры в
`tests/named_normal.log`, `tests/named_wait_timeout.log`, `tests/named_time_limit.log`
и `tests/named_parallel.log`. Без аргумента скрипт обновляет прежние неименованные примеры.

## Независимые процессы: функциональные требования на 7–8

Это третья реализация модели. Координатор не вызывает `fork` и не запускает
философов. Каждый философ это отдельный запуск программы `philosophers_participant`.
Общая FIFO-логика, реальные задержки, события, ограничения времени и статистика
используются из того же `src/fork_shared/simulation.c`, что и в первых двух версиях.

В первом терминале запустите координатора:

```bash
./bin/philosophers_coordinator demo 2 3 100 200 100 200 3000 100 42 fifo 10000
```

После сообщения `ГОТОВО` в двух других терминалах выполните:

```bash
# Второй терминал
./bin/philosophers_participant demo 1
# Третий терминал
./bin/philosophers_participant demo 2
```

В одном терминале те же независимые процессы можно запустить оболочкой:

```bash
./bin/philosophers_coordinator demo 2 3 100 200 100 200 3000 100 42 fifo 10000 &
coordinator_pid=$!
# Дождитесь сообщения ГОТОВО, затем выполните следующие команды.
./bin/philosophers_participant demo 1 &
./bin/philosophers_participant demo 2 &
wait "$coordinator_pid"
wait
```

`SESSION` содержит 1–32 символа `A-Z`, `a-z`, `0-9`, `_`, `-`. Координатор принимает
после имени сессии те же параметры, что и прежние программы. `ID` - номер от 1
до N. Запуски с некорректными аргументами завершаются до создания IPC и журнала.
Сначала должен быть запущен координатор, тк раннее подключение получает понятную
ошибку, после `ГОТОВО` его можно повторить. На подключение всех N участников
отводится 10 секунд. До подключения последнего философа модельное время не идёт.
Если кого-то не хватает, сессия останавливается с кодом 1 и освобождает ресурсы.

Координатор создаёт `/philosophers-session-SESSION`, а также семафоры
`/philosophers-session-SESSION-mutex` и `/philosophers-session-SESSION-wake-i`.
В отличие от версии на 6, имена сохраняются во время сессии, каждый участник сам
выполняет `shm_open`, `mmap` и `sem_open`, без наследования от координатора.
Философ открывает все персональные семафоры, потому что общий алгоритм может
разбудить любого следующего участника FIFO. Под mutex философ регистрирует PID
в своём слоте, повторное подключение одного ID отклоняется. Начало работы
разрешается только после подключения всех участников.

У каждого сеанса свой журнал `philosophers-SESSION.log` в каталоге координатора.
Участники получают его абсолютный путь через общую память и дописывают события
с `O_APPEND` под общим mutex. Их можно запускать из другого рабочего каталога.
Каждый философ выводит свои события в свой терминал. Координатор выводит снимки
состояний и окончательную статистику. Полная последовательность есть в журнале.
Два разных имени сессии могут работать одновременно, в том числе из одного
каталога. Повторный координатор с тем же именем не перезаписывает журнал первого.

Ctrl+C / SIGTERM координатору или участнику останавливает всю модель. Координатор
будит ожидающих, даёт участникам выйти и затем закрывает/удаляет свои семафоры
и shared memory.
Погибший или остановленный философ обнаруживается по PID и состоянию `/proc`.
Ожидание занятого mutex ограничено,  если его владелец погиб, сессия завершается
с ошибкой вместо зависания.

При частичном создании удаляются только успешно созданные объекты. Совпавшие
чужие имена не удаляются (`O_EXCL`). `SIGKILL` координатору и выключение ОС не дают
процессу выполнить очистку, после такого исхода имена могут остаться в `/dev/shm`.
Используйте Ctrl+C / SIGTERM для обычного прерывания. Порог ожидания mutex в 2 секунды
также означает, что сильно зависший терминал/диск может вызвать аварийную остановку.

`philosophers_session_tests` проверяет 2 и 5 участников, FIFO и владение вилками
по журналу, отсутствие детей у координатора, регистрацию и повторные номера,
запуск из другого каталога, SIGINT/SIGTERM, SIGKILL/SIGSTOP участника, оба лимита,
неполный набор участников, два одновременных сеанса, некорректный ввод,
сохранность чужого семафора и объекта памяти, отсутствие своих IPC после выхода.

```bash
ctest --test-dir build --output-on-failure
bash tests/run_session_examples.sh
```

Скрипт запускает отдельные программы оболочкой и сохраняет результаты наборов
из `tests/scenarios.txt` в `tests/session_normal.log`, `tests/session_wait_timeout.log`,
`tests/session_time_limit.log`, `tests/session_parallel.log`. При неудаче он указывает
каталог с диагностикой.

## Независимые процессы с POSIX-очередями: требования выше 8

Четвёртая реализация использует `mq_open`, `mq_timedsend`, `mq_timedreceive`,
`mq_close`, `mq_unlink` из POSIX. Состояние стола хранится в обычной памяти
координатора. Философы не открывают shared memory и не меняют вилки напрямую:
они сообщают о голоде и окончании еды, а координатор ведёт FIFO и выдаёт обе вилки.

Первый терминал:

```bash
./bin/philosophers_mq_coordinator demo 2 3 100 200 100 200 3000 100 42 fifo 10000
```

После сообщения `ГОТОВО` второй терминал:

```bash
./bin/philosophers_mq_participant demo 1
```

Третий терминал:

```bash
./bin/philosophers_mq_participant demo 2
```

Координатор не запускает философов через `fork`. Имя `SESSION`, диапазон ID,
параметры, лимиты, коды завершения и 10 секунд на подключение такие же, как в версии
7–8. Все аргументы проверяются до открытия журналов и создания IPC. Параметры
передаются участнику сообщением CONFIG. Каждый участник открывает существующие
очереди и семафоры самостоятельно, поэтому запуск из другого каталога допустим.

Имена объектов для сессии `demo`:

| Объект | Имя | Назначение |
|---|---|---|
| Общая очередь запросов | `/philosophers-mq-demo-requests` | Сообщения от философов координатору |
| Очередь ответов философу i | `/philosophers-mq-demo-reply-i` | Параметры, разрешения и остановка |
| Именованный семафор `wake` | `/philosophers-mq-demo-wake-i` | Уведомление о сообщении в очереди ответов |
| Именованный семафор `claim` | `/philosophers-mq-demo-claim-i` | Только один процесс может занять место i |

В именах i начинается с 0, в командной строке ID начинается с 1. Координатор
создаёт объекты с `O_CREAT | O_EXCL` и правами 0600. Участник сначала занимает
`claim` через `sem_trywait`, чтобы повторный ID не смог забрать чужой ответ.
Затем отправляет JOIN с номером и PID. После регистрации всех философов координатор
отправляет START. Все ответы сначала помещаются в очередь, затем выполняется
`sem_post(wake[i])`, так как философ ждёт уведомление и читает сообщение.

Цикл участника:<br>
THINK -> получить длительность -> реально подождать -> HUNGRY ->
получить EAT_ALLOWED -> реально поесть -> FINISH.<br>
Координатор проверяет допустимость
перехода состояния, назначает обе свободные вилки первому в FIFO и сохраняет
статистику. Следующее размышление разрешается CONTINUE, после последнего цикла
философ ожидает общей остановки. Один приоритет запросов сохраняет их порядок
поступления. STOP имеет повышенный приоритет, чтобы обогнать устаревшие ответы
при аварии. Версия протокола, размер сообщения, ID, PID, тип и порядок действий
проверяются.

Размышление и еда происходят в независимых процессах. Время ожидания вилок
измеряется от обработки HUNGRY до разрешения EAT_ALLOWED координатором. Событие
начала еды в журнале означает выдачу разрешения, фактическое получение ответа
может произойти немного позже из-за планировщика. FINISH принимается только
после истечения назначенной длительности. Философы могут есть параллельно,
если не являются соседями. `display_delay=0` отключает снимки, но не задержки еды.

Полный журнал и статистику пишет только координатор в `philosophers-mq-SESSION.log`.
Повторный координатор с тем же именем завершится с ошибкой до перезаписи журнала.
Два разных сеанса могут выполняться одновременно. При остановке координатор
рассылает STOP, ждёт EXIT и закрывает/удаляет очереди и семафоры. Независимые
философы сами закрывают свои дескрипторы, `waitpid` для них координатор не вызывает.
SIGINT/SIGTERM участника передаётся координатору сообщением ABORT. Гибель и SIGSTOP
участника определяются по PID и `/proc`, так как неответившие процессы останавливаются
принудительно. После исчезновения координатора философ завершает ожидание.

Отправка сообщения ограничена 100 ms, ожидания проверяются интервалами 10 ms.
После STOP координатор ждёт подтверждений до секунды. Переполнение очереди даёт
ошибку, а не бесконечное ожидание. Каждая очередь вмещает четыре сообщения
размером `sizeof(MqMessage)`.

Как и в версии 7–8, SIGKILL координатора или выключение ОС не позволяют ему
выполнить очистку, имена могут остаться. Обычная остановка - Ctrl+C или SIGTERM.
Протокол предназначен для локальных программ одного пользователя, поле PID
в сообщении не является проверкой подлинности враждебного отправителя.

```bash
ctest --test-dir build --output-on-failure
bash tests/run_session_examples.sh mq
```

Новые проверки используют тот же C-тестовый стенд, что и версия 7–8, и дополнительно
проверяют неверные сообщения, заполненную очередь, приоритет STOP, сохранность
чужой очереди и искусственные ошибки `mq_open`, `mq_timedsend`, `mq_timedreceive`,
`sem_open`, `sem_post`, часов. Подмены из `tests/mq_faults.c` включены только в
тестовые бинарники. Примеры находятся в `tests/mq_normal.log`, `tests/mq_wait_timeout.log`,
`tests/mq_time_limit.log`, `tests/mq_parallel.log`.

## Что где лежит

- `src/common/`, `inc/common/` - общий код: консоль, параметры, имя сессии и базовые заголовки.
- `src/fork_shared/`, `inc/fork_shared/` - версии 4--6: запуск, общая память и оба вида семафоров.
- `src/independent/` - версия 7-8 с независимыми процессами и общей памятью.
- `src/mq/`, `inc/mq/` - версия выше 8: очереди сообщений, координатор и участник.
- `tests/` - тесты и примеры вывода.
- `tests/faults.c` - подмены системных вызовов для проверки аварийных исходов.
- `tests/test_session.c` - проверки независимой версии на 7–8.
- `REPORT_2.md` - исторический отчёт по многопоточному второму ДЗ.
- `build/` - файлы сборки, `bin/` - программа и тесты.
